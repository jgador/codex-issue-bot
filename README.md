# Codex Issue Bot

Reusable GitHub Actions workflows that route issue-driven work to [openai/codex-action](https://github.com/openai/codex-action). Use them to spin up a Codex-powered branch for new issues or iterate on follow-up comments.

## Quick start

1. **Add secrets** to the consuming repository:
   - `OPENAI_API_KEY`
   - `OPENAI_RESPONSES_ENDPOINT`
2. **Reference the reusable workflow** from your repository. Example for `/codex` issues:

   ```yaml
   name: Codex Issue Automation
   on:
     issues:
       types: [opened]

   jobs:
     codex:
       uses: your-org/your-repo/.github/workflows/codex-issue-agent.yml@v1
       secrets: inherit
       with:
         base-branch: master         # optional override
         branch-prefix: codex/issue-
         require-owner: true
         # prompt: |
         #   Provide your custom instructions here.
   ```

   To handle iteration requests from comments, add another workflow:

   ```yaml
   name: Codex Comment Automation
   on:
     issue_comment:
       types: [created]

   jobs:
     codex:
       uses: your-org/your-repo/.github/workflows/codex-comment-agent.yml@v1
       secrets: inherit
       with:
         base-branch: master
         require-owner: true
   ```

3. **Open an issue with `/codex`** using the bundled template `.github/ISSUE_TEMPLATE/codex-request.md`. The workflow checks ownership, sets up a branch, runs Codex, pushes commits, and comments the final summary.

## Workflow inputs

| Input           | Default            | Description                                                  |
|-----------------|--------------------|--------------------------------------------------------------|
| `base-branch`   | `master`           | Branch used to seed or update the working branch.            |
| `branch-prefix` | `codex/issue-`     | Prefix for autogenerated branch names from issue numbers.    |
| `require-owner` | `true`             | Restrict runs to issues/comments authored by the repo owner. |
| `prompt`        | `""`               | Full prompt override passed to Codex. When empty a sensible default is generated. |

All other behaviour (Git author config, branch push, comment response) is handled inside the reusable workflow.

## Outputs

Codex’s final response is posted back on the originating issue or comment. If you need to process that message further, capture `steps.run_codex.outputs.final-message` in a downstream step of your caller workflow.

## Templates and prompts

- Issue template: `.github/ISSUE_TEMPLATE/codex-request.md` pre-populates `/codex` and a branch hint (`codex/issue-{{ number }}`).
- Custom prompt: pass the `prompt` input to supply your own instructions; omit it to rely on the built-in context/tasks/constraints.

## Security notes

These workflows run `openai/codex-action@v1`. Review its [security guidance](https://github.com/openai/codex-action/blob/main/docs/security.md) and choose trusted triggers (`require-owner`, branch filters) before granting write permissions. Restrict secrets to repositories and environments you trust. Continuous monitoring is recommended for branches that Codex auto-updates.

Pin the reusable workflow reference to a released tag (for example `@v1`) so consumer repositories get predictable behaviour as you iterate.
